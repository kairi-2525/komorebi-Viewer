# komorebi 0.1.6

YouTubeとツイキャスのコメントをまとめ、Jevの判定に応じて配信者だけの表示・配信画面への表示・選択した音声エンジンでの読み上げを制御するWindows向けアプリです。

公式配布は [komorebi-Viewerのリリース](https://github.com/kairi-2525/komorebi-Viewer/releases) です。本体はZIPを展開して使います。セットアップEXEはOBSプラグイン用です。

## 動作環境

- Windows 10/11、64 bit。Node.js 24.19.0は同梱しています。npmや開発用ツールは不要です。
- Microsoft Edge、.NET Framework 4.8。音声・専用ウィンドウの補助プログラムを初回に準備します。
- 判定には利用者自身のTypeSafe/JevアカウントとAPIキーが必要です。
- 読み上げにはVOICEPEAK、またはkomorebi専用の起動方式で導入したAivisSpeech Engineが必要です。製品本体・音声ライブラリ・Engineやモデルは同梱しません。
- AivisSpeechは同梱`tools/aivis/setup.mjs`で指定フォルダーへ導入します。GPUを使う場合は「音声」→AivisSpeechの接続・起動設定で「GPUを使って合成する」を選び保存してください。旧版からの更新時は同梱setupを既存Engineフォルダーへ再実行し専用launcherも更新します。無音合成確認と、選択した音声出力先へ実際に流す「試聴（固定文）」を使い分けます。
- 同梱OBSプラグインはOBS Studio **32.0.4 / 32.2.2で動作確認済み**です。他の版も未検証の試験導入として進められます。OBSなしでもアプリ本体を利用できます。

## 起動

1. ZIPを任意の書き込み可能なフォルダーへ展開します。ZIPの中から直接実行しないでください。
2. `run.cmd`を開きます。既定ブラウザで管理画面が開きます。
3. 「接続」からサービスと連携し、配信先を設定します。認証用Client IDの登録・公開状態は配布者の設定によります。
4. 接続画面のAPIキー入力欄でJevキー等を入力し、「暗号化して保存」を押します。登録はこのWindowsユーザー用に暗号化保存され、次回起動時に復元します。初回の外部判定・公開・読み上げはOFFです。
5. 必要な許可を1つずつ有効にします。非公開コメントの本文・表示名は公開ページへ送りません。

終了するときは起動ターミナルでCtrl+Cを押すか、管理の「診断・削除 → アプリの更新」にある「アプリを終了」を使います。更新後はこのボタンで正常終了できます。緊急停止後は自動再開せず、管理画面で明示的に停止解除します。設定や停止状態はローカルに保存します。デバッグログの保存・ダウンロード機能は含みません。

受信したコメントは外部の命令として実行しません。公開・読み上げを許可する前に、配信での利用条件と判定基準を確認してください。サイト上での削除・BANには別の操作用認証が必要で、通常の連携だけでは実行しません。

## OBS

別PC側のOBSを操作できるCodexへ、新規設置と既存環境の更新反映を任せられます。[プロンプトのURL](https://github.com/kairi-2525/komorebi-Viewer/blob/main/OBS_SETUP_PROMPT.md)と「このプロンプトを読んで作業を開始して」を渡してください。毎回最新の手順を取得し、以前読んだ手順の版が不明でも現在の状態から必要な変更だけを行います。同梱の `OBS_SETUP_PROMPT.md` が古い場合も公開URLを確認します。認証が必要な操作は人が行えます。調整済み標準Jev設定は同じ手順が参照する公開JEV_DEFAULTS.jsonから取得できます。独自設定を移す場合だけ別の正本が必要です。

1. OBS Studioを通常終了します。既存プラグインがある場合は、戻せるように先にバックアップしてください。
2. 展開フォルダーの `installers/komorebi-obs-plugin-0.1.6-win-x64-setup.exe` を開き、Windowsの管理者権限確認を許可します。
3. OBSとkomorebi本体のフォルダー、表示された実際のOBS版・使用ビルド・動作確認の有無を確認し、「インストール」を押します。未検証版も試せます。起動中のOBSへは導入しません。
4. OBSを起動し、「ツール → komorebi」で「起動・接続」を押します。「ドック」メニューからコメント・ギフト・操作のドックを表示できます。

本体のフォルダーは展開した場所に置き続けてください。以前のOBS設定が別の本体を参照している場合は、「ツール → komorebi」の詳細設定で本体のフォルダーを変更します。

未検証版では、32.2系以降に32.2.2用、それ以前に32.0.4用のプラグインを選んで試します。たとえば32.2.3でも版の違いだけでは導入を止めません。導入完了は動作確認の完了ではないため、OBSの起動・3ドック・本体接続・正常終了を確認してください。起動できない場合はOBSを終了し、バックアップしたプラグインを元の場所へ戻します。OBSを勝手に更新・降格する必要はありません。

プラグインは `C:\ProgramData\obs-studio\plugins\comment-viewer-jev-docks` に導入します。既存の同名プラグインは更新します。OBSでの配信・録画は開始しません。既存の設定、ソース名、ドック配置は引き継ぎます。

削除はOBSを通常終了してから、Windowsの「インストールされているアプリ」で「komorebi OBSプラグイン」を選びます。本体とOBSの設定は残ります。削除用の補助EXEはWindowsの再起動時に削除されます。

コマンドでの導入も利用できます。管理者権限のターミナルで `run.cmd install:obs-docks` を実行します。別の場所のOBSには `-Obs "OBSのフォルダー"` を付けます。

## Jevの標準設定

判定はChoiceの5択（表示統合OFFで6択）です。4問一括（段階判定）の切替は廃止しました。新規設定にはこのPCで調整した一般基準とJev1.14.0を採用し、文脈8件／600秒／2000文字、NG10回が標準です。秘密・履歴・端末情報を含まない13項目を同梱 `tools/JEV_DEFAULTS.json` として提供します。profileRevisionは本体の版とは別です。

更新時には保存済み独自基準を保持します。旧4問の独自基準は分類基準へ移し、既知の旧既定基準だけを新標準へ更新します。保存済みの文脈・NG回数などは維持します。標準JSONを既存環境へ適用する場合は、OBS反映用手順に従って対象項目だけを比較・保存・読戻してください。公開・送信・読み上げの許可や認証をJSONから変更しません。

## デモ

```powershell
.\run.cmd demo
```

外部サービスやAPIキーを使わず、合成したコメントとローカルの模擬サービスで動作します。デモの音声は無音で、実VOICEPEAKの音色確認には使えません。通常モードの接続失敗をデモ成功へ置き換えません。

## データと更新

入力欄から登録したAPIキーはこのWindowsユーザー用に暗号化保存され、起動時に復元します。空欄のまま保存すると既存値を保ち、個別削除・全削除では環境変数に同じキーがあってもアプリで再採用しません。環境変数そのものを変更する処理はありません。OAuth連携は別管理です。復元に失敗した場合は画面にエラーが出るため、保存情報を明示的にリセットしてから再入力します。保存済みキーの本文は画面へ返しません。別PCではそのPCで登録してください。

管理用URL、認証情報、`.data`、実行中に生成される`.runtime`の内容を共有しないでください。初回管理URLはローカル保存先の `bootstrap.url` にも保存します。コメント本文は短期保持し、正常終了・次回起動・明示消去で消します。リスナー集計や設定は本文とは別に保存します。

0.1.1以降の配布ZIPにはアプリ内更新を含みます。管理の「診断・削除」タブにある「アプリの更新」で「更新をチェック」を押し、新しい版がある場合は「更新をダウンロード」を押します。公開配布先のZIP・SHA256・内部のファイル一覧を検証した後に、「更新して再起動」を選べます。起動時や定期的な自動確認・自動適用は行いません。

適用前に入力中の設定を保存または取り消し、入力中の認証情報も保存または消去してください。適用すると、配信への接続・判定・公開・音声を停止して本体を再起動します。保存済み設定・認証情報・履歴は引き継ぎます。配信を終えてから更新してください。管理画面が開かない場合は展開フォルダーの `run.cmd` で起動し直します。更新確認・ダウンロードが失敗した場合はエラーを表示し、成功扱いにはしません。

0.1.0にはアプリ内更新がありません。0.1.1では更新確認がエラーになる場合があるため、その場合も手動で0.1.6へ更新してください。本体とOBSを通常終了し、既存の本体フォルダーをバックアップします。公式配布の0.1.6 ZIPを展開し、その `komorebi-0.1.6` フォルダーの中身を、既存の `run.cmd` と同じ階層へ上書きしてください。既存の`.data`や、ZIPにない`.runtime`の保存情報を削除しないでください。既存フォルダーの `run.cmd` で起動すると保存先と設定を引き継ぎます。OBSプラグインの導入・更新には、展開フォルダーのセットアップEXEを使います。アプリ内の本体更新が、管理者権限で導入したOBSプラグインを自動更新することはありません。

自分の`.data`や保存先移行情報を、他人へ配布するZIPに含めないでください。同梱の初期`.runtime`には補助実行ファイルだけが入っています。
